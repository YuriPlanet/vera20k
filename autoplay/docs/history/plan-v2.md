## 0. 现状一句话

引擎侧 L1（behavior）/ L2（control）/ L3（strategy）三层齐全，L3 的 retail 策略已经相当完整；玩家侧接入也已打通（热键 → `install_auto_play` → `AutoPlayHost`），v2 策略以 `VERA20K_BRAIN=v2` 与 retail 策略并存。**缺口集中在三处：控制层的玩家可感知边界（限制 2/4）、清单里明确没做的功能（渗透优先级、超武、分基地、主产切换、中立设施取舍）、以及外部接口的接线。**

| 层 | 位置 | 状态 |
|---|---|---|
| L1 执行 | `src/sim/behavior/` | ✓ 目标词表、单一命令漏斗、托管微操 |
| L2 控制 | `src/sim/control/` | ✓ 棋盘、预算、投影、感知、选址、外部接口契约 |
| L3 决策 | `src/sim/strategy/retail/`（22 文件，约 1 MB） | ✓ 成熟，是默认大脑 |
| L3' 决策 | `autoplay/`（vera20k-autoplay） | ◐ 独立 crate，环境变量切换，未达可替默认 |
| 接入 | `src/app/input/dispatch.rs:2153` | ✓ 热键、域开关、`take_back` |

## 6. 推进顺序

### P0 控制层补齐（玩家可见，最影响"能不能用"）

1. **不可控单位排除**（限制 2）：按类型/状态排除伞兵运输机等，加入 board 的准入。
2. **Battle control offline 停止**（限制 4）：在 `AutoPlayHost::step` 前加门，读 `scenario_session` 的 battle-control 状态。
3. 三条域开关补 HUD/文档（限制 1 已有，补可见性）。
4. 每局独立补回归测试（限制 3 已有）。

### P1 功能缺口（按"用户明确说重要"排序）

1. **占领敌方建造场 + 打包撤离**（3.5.6 / 4 的"打包回 MCV"）——用户标注"重中之重"。
2. **渗透优先级**（3.5.5）：矿厂 > 工厂 > 实验室 > 超武；引擎已支持 50% 偷取。
3. **超武使用**（3.7.2）：何时放、放哪里。
4. **分基地与矿脉**（3.1.9）：`ore.rs` 已有读图，补"矿脉边落分基地"。
5. **主产切换**（3.1.12）。
6. **中立设施价值评估**（3.6.1/3.6.4）：在敌方区域的、太远的，放弃或破坏。

### P2 微操深化

分子弹、卡射程、保护英雄、引诱扛伤、自爆处理、感染处理、掩护；矿车微操（避让/选矿）；海空运输。

### P3 外部接口

`external.rs` 接线（进程边界 + 稳定 schema + 一版示例），`pilots.rs` 扩展。

### P4 回归

32 条历史问题逐条跑图回归；每局用 `check_acceptance.py` 的 T1–T8 验收。

## 7. 工作流约定（本轮起执行）

- **每次构建或测试之后清理缓存**：`python -m tools.cargo_run --trim-cache`；空间不足时删 `<target>/owned-worktrees/<hash>/incremental` 与废弃 profile 目录。E: 只剩约 12 GB，`E:\Projects\vera20k\target` 占 63 GB（另一条线），需要时另行确认。
- 构建统一走 `python -m tools.cargo_run`，测试一律 `--lib`。
- 每次只改一个可归因的变量，跑完记一行结论。
