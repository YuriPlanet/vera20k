## Consumed schema

`inputs` holds physical layer/asset/ART identities and original constructor/read
observations once. `rows` contains the three cases above:

- `input` and `preparation`: admitted pose/foundation, literal guard/session
  bytes, declared House boundary and actual native58-damage preparation.
- `phases`: before preparation/fire, optional schedule start, after fire,
  actual UnInit and before/after deferred destruction. Each retains source and
  target outcomes plus all full Main/Scenario/Mapgen buffers and request count.
- `source_packets`/`target_receivers`: semantic source/target/null roles,
  packet/Warhead/flags/alias identity and actual health/result transitions.
- `calls`, `anims`, `lifecycle`: selected actual class returns, native decisions,
  DeathWeapon effects, source expiry and cleanup order. DoAction compares AL;
  void returns and unconsumed high bytes/pointers are omitted.
- `normal_fire_tail_visits`, `fire_writes`, `target_writes`, `timer_writes`:
  distinguish absent normal emission/rearm/stamp effects from the real burst0
  reset, target clear and sequence/mission timer writes. Opaque middle words are
  omitted; repetitive dying timer writes are represented by compact stage visits.
- `rng_requests`, `death_visits`, `original_code_unchanged`: actual stream/raw
  ordering,15-stage membership/health observations and unchanged original PE
  code. RNG states are observed, not recalculated from Rust.

Rust consumers exercise the existing direct receiver and ordinary object visit,
production retail readers/effect bindings, source cleanup and the affected
target. The oracle itself compares every retained field. Raw pointers, unused
register/stack bytes, per-instruction writes, disassembly and run receipts stay
outside the repository.
