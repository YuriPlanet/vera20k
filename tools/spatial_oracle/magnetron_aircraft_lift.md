# Magnetron aircraft lift

Run from the repository root with the retail executable and extracted `ini/`
available:

```text
python -m tools.spatial_oracle.magnetron_aircraft_lift --check
```

`--write` deliberately replaces the JSON and provenance sidecar. Import and
`--help` are inert without retail files, in normal and optimized Python.

The ten hit histories execute original instructions from `0x46963A` to
`0x469AA4`. Accepted hits call `Techno::ImbueLocomotor` (`0x710000`), the
original Jumpjet COM factory and constructor, BeginPiggyback, the actual class
destination setter (`Aircraft 0x41AA80`), shared Foot setter (`0x4D94B0`), and
installed Jumpjet Move_To (`0x54B1C0`). Aircraft layer queries use the original
Aircraft/Fly virtual methods. The original code and vtable region are checked
for mutation; movement Process and Find_Path are forbidden.

Selected physical fields from RULESMD, optional LANGRULE and MPBattleMD pass
through the original type and weapon readers. The corpus records those lexical
inputs and resulting type scalars. This is selected-field reader evidence,
not complete retail object/map initialization. The firer is at `(1408,2688,0)`;
the victim is at `(2688,2688,0)`. The supplied flat map and zone plane allow the
original nearby-location search. Jumpjet rewrites the initial object NavCom to
a Cell and receives the original search's destination. A prepared reload-pad
row supplies reciprocal radio contact and verifies the original setter breaks
it. Production docking and full-shot reachability belong to the Rust retail
integration tests.

Original CRT initializer `0x48E480` (table entry `0x812B28`) initializes the five
Infantry placement offsets used by Jumpjet's non-Unit destination arm. The
emitted offsets are runtime outputs of that initializer, not sparse-image
zeros or a destination supplied by the fixture. Scenario RNG starts at seed1;
each hit history also records the next original Random result after its final
snapshot, so its placement draws can be compared independently of coordinates.

ORCA and BEAG are accepted on the ground, while the supplied airborne ORCA,
Infantry and strength-equals-size controls are refused. MTNK exercises the
existing Unit route. The original release (`0x70FEE0`) is executed on the joined
history. The altitude row supplies Z=300 before release; it does not simulate
the rise. Ground release keeps Jumpjet moving and the original Foot restore
gate initially refuses. A separately labeled supplied-settled control clears
only its moving byte, then executes the original restore gate and EndPiggyback
to recover Fly. That control does not establish a full flight or landing.

`landing_controls` enter original State5 at `0x54CE26` and stop at `0x54CE6A`.
Actual Aircraft CanEnterCell and Cell wheel-clear (`0x4834A0`) run on clear and
impassable cells. They distinguish ordinary entry0 from the aircraft-specific
wheel refusal that forces entry7.
The crop starts after State5's earlier movement/Mark work. A direct read after
the joined hit measures Foot occupation flag `+0x6B6` as true: original Imbue
`0x7101CF` writes1. The supplied cell still has raw ground/deck occupation0 and
no aircraft member, since no movement/Mark prefix has executed. These are
controlled gate inputs, not evidence of the complete State5 prefix. The
synthetic Rust test disables occupation only as an adapter to preserve that
measured empty gate cell while entering its wider State5 owner; this does not
represent the native post-hit flag.

`impact_controls` enter the original terminal tail (`0x54D045`) after supplying
its reached-landing boundary, then execute real virtual dispatch through the
Aircraft INoticeSink at object+8 to `0x41BC30`. The body runs through return:
native strength/health selection, floating conversion/clamp, coordinates,
warhead selection, credit ordering and UnInit request are observed. The
original AirTracker is initialized and its removal runs. Rules C4, death weapon
and projectile are supplied distinct identities. Bullet creation returns a
prepared object on the original Bullet vtable; mark, detonation, release,
RecordKill and UnInit are declared no-op effect boundaries. Thus the corpus
proves both requested C4 impacts and their order/arguments, not explosion
propagation, deletion or resulting map state. Unlifted, current-health,
negative multiplier and absent-manipulator controls bound that claim.

Windows COM activation is a transport seam: it enters the original executable's
Jumpjet factory with the requested IID and returns its real interface. OleRun
returns S_OK. Shared reader helpers supply allocation, TLS, INI cache and
optional asset leaves. No class destination, Jumpjet, landing, admission or
Notice decision is replaced with an expected result.

The Rust comparison consumes the ten hit/release rows through the production
owners, with the same selected rule layers and prepared scene boundaries.
Separate Rust tests exercise the two landing rows and the five impact rows,
and distinguish Aircraft C4/C4 damage from Unit Crush/C4 damage on an adjacent
surviving receiver. The physical retail regression orders ORCA and BEAG to
attack, return, reload and dock before an enemy TELE attacks. It saves and
reloads while held, then requires natural release and restoration of Fly.
These whole-frame checks are Rust integration evidence, not a native flight
capture. No snapshot field or format version changes.

Suggested interactive check: in stock
skirmish, let a Harrier or Black Eagle return and reload at its airfield, then
attack it with an enemy Magnetron. Check pad contact release, lift/pull, and
release over clear ground and over a blocking object. Save while held and
resume. Compare those outcomes side by side with the original; frame timing,
presentation and complete fall trajectories remain outside this corpus.
