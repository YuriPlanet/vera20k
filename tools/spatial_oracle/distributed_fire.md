# DistributedFire and its numeric prerequisites

Run with the supported executable selected as described in
[the native runner](../native_oracle.md):

```sh
python -m tools.spatial_oracle.distributed_fire --check
python -m tools.spatial_oracle.rearm_timer --check
```

Explicit `--write` regenerates a corpus and its binary-identity/replay-command
sidecar. No retail executable or repository source hashes are retained.

`distributed_fire.json` preserves its original151 rows:126 complete
`TechnoClass::DistributeFire709550` selections and25
`TechnoClass::PointerExpired707BCE..707CA4` tail controls. These cover ordered
candidate/score/history operations, strict signed comparisons, first ties,
first-removal and original vector operations. Empty candidates clear history
without invoking AssignTarget; nonempty nonpositive scores can assign NULL.
Raw EAX, allocator capacity and fixture pointer addresses are not a Boolean
selection result. The six explicitly scripted allocator/setter mutation rows
remain boundary stress controls, not gameplay behavior to implement.

The actual native setter, scanner eligibility/candidate production, FireAt
history append/mission exception, enclosing lifecycle dispatch and snapshot
transport remain outside those151 controls. Their existing OS allocation,
locking and copied-owner setter boundaries are enumerated in the sidecar.

The additive `air_query` controls reuse the tracker initializer and machine
owner in `fly_landing_phase.py`; the legacy41 landing rows remain unchanged.
Original startup412870..4128D6 stops before CRT exit registration. Original
bucket/current-vector vtables, flags and growth remain intact, with supplied
spare-capacity storage avoiding allocation. Sparse opaque bucket tokens are
query inputs, not a native actor-admission claim. Whole412B40 runs Cell486840
and413A30 coordinate conversion, signed map-span division, packed16 endpoint
clamping and vector copying. Original4137A0 then drains the front.

Seven controls cover radii0/1, an interior query spanning cardinal/corner
runs, nonsquare/nondivisible spans, lower/upper edges, retained entry order
and repeated tokens. `copied_bucket_order` includes empty and repeated
buckets observed at original copy-body count reads; `copied_ids` observes
native writes, and `drained_ids` records actual front returns. No Rust/helper
calculation supplies those values. Hooks only observe, reject RNG and check
source Cell/Scenario state and original instructions/vtables unchanged.
Spans64..128 and admitted nonnegative centers bound the controls; map spans
below20, signed16 wrap outside normal maps, OOM, actor membership/migration,
full scans and world update order are not certified.

`rearm_timer.json` preserves89 fire and96 Guard rearm rows. Six additive
`guard_distributed_rng` rows execute4D52A9 through the actual return, original
Unit getter741490 and Scenario RandomRanged65C7E0. The earlier mission cadence
in EBP, type/count and timer fields are supplied. The full RNG input comes
from the existing RNG owner's native-produced `(0,2)` continuation, with
rejection sampling, in `rmg_oracle/vectors/rng.json`. Original raw-word stores
65C84B and complete before/after state distinguish requests from raw draws.
The controls cover positive candidate count1/2, empty/flagfalse fallback and
running/paused rearm. They do not execute earlier Guard effects, mission Rate
conversion, passive-scanner scheduling or complete gameplay frames.

Rust consumers are the GameEntity DistributedFire owner and its expiry path,
the shared occupancy/EntityStore air query used by GreatestThreat and AoE,
and the production Guard cadence owner. Existing native scanner171 controls
and RNG98-call histories retain their separate bounds. Production tests must
join actual retail AEGIS Guard acquisition, collected scores/order, Medusa
shots, history, target assignment, timers/RNG and cleanup; these small
corpora alone do not establish whole-mechanism or match parity.
