# Manual primary factory: original self-action, Event17 and consumer

Run from the repository root with the original `gamemd.exe` selected:

```sh
VERA20K_BUILDING_CONSTRUCTION_ASSETS=/path/to/extracted-retail \
  python -B -m tools.spatial_oracle.building_construction --manual-primary --check
```

The directory contains the existing construction profile's physical RULESMD,
ARTMD, SOUNDMD, MPBattleMD and selected SHPs, plus `Hills.map`. The optional
LANGRULE layer is absent in this selected installation. `ini/evamd.ini` is the
unlayered retail cue source. `--write` deliberately records original execution;
the sidecar records executable identity, replay command and evidence bounds.
The default and `--joined` modes retain their separate payloads.

This extends the existing `JoinedFixture`, native input readers, allocation,
map, RNG tracing and `NativeCallTrace` owners. It introduces no native VM,
INI parser, primary-selection algorithm or random-number implementation.

Native `AC4B84` counts actor paths containing at least one remaining command.

even while the empty path remains executing until acknowledgement. Clearing

calls `638840` at `701585` before replacing the owner, releasing any old
nonempty path. Cleanup uses the actor's effective House: current owner,
redirected to the current player for a controlled House. Ordinary capture
therefore clears rather than transfers a path count. Append increments by
event issuer; delayed old-issuer append after capture is a distinct bound,
not evidence that every unusual ownership history can be reduced to a live
owner count. The current Rust planning owner already retains empty executing
