# Ordinary cell overlays at the shroud boundary

`bridge_shadow_render.py --shroud-admission` extends the existing bridge/native
image/palette owner. It runs the **original complete** `47FB90` body rectangle,
`47FDE0` shadow rectangle, `47F6A0` body and `47F510` shadow callers with live
retail low wood bridge types, varying the supplied `Cell+12C/+130` words.
There is no substitute visibility rectangle or draw sink in this mode.

```sh
python -m tools.spatial_oracle.bridge_shadow_render --shroud-admission --check
```

Select `RA2_DIR` or `VERA20K_GAMEMD_EXE` as described in
[the native runner](../native_oracle.md).
The adjacent `.meta.json` records tool source identity, inputs, substitutions and
coverage. The historical default bridge payload remains a separate corpus.

## Established native behavior

`Tactical::Cell_ContentRendering @ 6D6D10`, called by dirty/full rectangle
orchestration `6D3290`, performs two map-cell sweeps. For each actual overlay
(`Cell+44 != -1`) it obtains `47FB90` or `47FDE0`, intersects with the current
clip (`421B60`), and calls the respective body/shadow renderer only for a
positive rectangle. This is **drawing geometry**, not cell exploration admission.
Original bytes for this caller and prerequisites are saved with their hashes.

The `568300` predicate reads only Map `+F4/+F8` and supplied cell coordinates.
Its inequalities describe the diamond-shaped map boundary. Four native executed
controls cover inside and outside cells; it does not read the explored words.

The original rectangle functions read live overlay identity, type/SHP/frame,
cell position and `480110` drawing lift. Their ordinary low-bridge paths do
not read `Cell+12C/+130`. Thirty executable rows cover `LOBRDG01`, `LOBRDG02`,
`LOBRDG08`, `LOBRDG09`, and shared high wood `BRIDGEB1`, each under six raw
visibility-word pairs (`+12C = 0x00, 0x08, 0x18`; `+130 = 0, 1`). Read hooks record
accesses overlapping these words. Every row reaches both original draw callers
and records their actual `4AED70` arguments and final RGB565/Z buffer hashes.

The low wood bodies bind from `ra2.mix/isotemp.mix/LOBRDG*.TEM` through the
original type constructor and complete rules/art reader. Native registry
ordinals are 74, 75, 81 and 82 (physical INI numbering is not the ordinal).
Only raw frame 1 is nonempty in these four physical files; it is supplied
explicitly. Their three shadow frames are empty, so the complete native Tactical
rectangle gate would omit those shadow calls. This corpus directly executes the
shadow caller as an additional negative-geometry control. High wood raw state 0
covers the shared nonempty shadow path; its frame redraw cache is supplied
invalid (`Cell+64 = -1`) before every control, allowing each new draw.

A separate native lookup (`586360`) tests `Cell+12C & 0x08` and returns invisible
when set. Raw bit values here are preserved rather than assigning Rust names to
potentially different flag encodings. All six variants retain identical
rectangles, draw arguments and final pixels within each prepared bridge type.

## Coverage and implementation implication

This establishes the absence of an anchor-cell exploration gate for these
ordinary cell overlay drawing paths. Removing VERA's early whole-cell explored
check allows its existing per-pixel shroud composition to clip the overhanging
art. Selection, simulation visibility and current identity remain independent.

This corpus supplies cell state, camera, maps bounds, brightness, RGB565/A/Z
surfaces and existing archive/lexical/allocator/TLS fixture boundaries. It does
**not** execute the entire Tactical iterator, native vision propagation,
Scenario loading, native shroud over these bridge pixels, save/load, GPU output,
or every ordinary overlay category. The saved caller bytes establish control
flow for the selected path; they are not an exhaustive alias or caller proof.
`bridge_shadow_render.py`'s older `traversal` deliberately substitutes map and
visibility rectangles and must not be cited as admission evidence.

The selected chain reads no simulation RNG, timer or detach calls in the
rectangle/draw bodies; the high bridge redraw cache is presentation state.
No native shader/pixel parity is claimed for VERA from these CPU controls alone.
