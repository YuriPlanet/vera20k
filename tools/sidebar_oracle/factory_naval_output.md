# Naval producer output and live animation cleanup

`factory_loss.py --naval-output` is an additive profile of the existing native
fixture owner. It writes `factory_naval_output.json` and its provenance sidecar;
the historical default, sale, sidebar and hold profiles remain independent.

```sh
VERA20K_GAMEMD_EXE=/absolute/path/gamemd.exe \
VERA20K_FACTORY_NAVAL_ASSETS=/absolute/path/naval-retail-cache \
RA2_DIR=/absolute/path/retail-install \
python -B -m tools.sidebar_oracle.factory_loss --naval-output --check
```

Use `--write` only to generate the new original-execution reference. Source,
Git and index must remain frozen throughout each native pass. Ordinary paid
Factory progress and player input belong to the connected Rust/runtime checks,
not this supplied completed-held-product boundary.

The admitted producer supplies only `6E4=1` among its lifecycle bytes: this is
the completed-opening guard whose real writer is `0x00446A6E` (the first-opening
admission checks `0x00445F89..99`). Constructor `0x0043B97E` retains damaged-art
byte `6E6=0`; `0x0043B98A` retains repair byte `6E8=0`; `0x0043B996` retains
enabled-stuff byte `6EA=1`. Those values are not forced by the fixture. The
real slot allocator later updates damaged-art state from its argument at
`0x0045189D..A5`. No repair input is issued.

`6E9` also stays at the actual complete constructor result. `0x0043BB29` calls
`0x00442C40`; its `0x00442CB2..CF` sequence calls the BuildingType's actual
vtC0 (`0x007E4630 → 0x00465960`), tests the returned resource, and writes1
only on the nonnull branch. The getter reads `Type+E00`; only `Type+1761`
admits its demand-load arm. An authored Buildup name alone is insufficient
evidence for `6E9=1`. Constructor and phase receipts record all five raw bytes;
full build-up resource/sale behavior remains outside this naval-output scope.

The three controls are:

- **`stock_dest_no_rally`**: native successful exit followed by deferred
  promotion and live Idle18 → Production8 → Idle18 cleanup. Whole BuildingAI
  and AnimAI execute, including same-pass newly appended Logic objects.
- **`sparse_actual_contact_slot2`**: a separate real constructed/on-map DEST
  occupies slot2 while earlier slots are null. Constructor capacity and supplied
  capacity are recorded independently. Extending a capacity below3 is a
  synthetic array-prior contrast, not proof that stock GAYARD owns three slots.
- **`inactive_scenario_refuses_unlimbo`**: explicit inactive-Scenario guard
  input, real FNPC/Unlimbo refusal and the already-queued Unload request. This
  is not evidence for a naturally obstructed retail yard; the production blocked
  exit regression covers that integration separately.

Each actual `ExitObject` and `MissionUnload 0x0044D880` call in `calls` has
`entry_state` and `return_state`, plus the observed return register/delay.
These contain current/queued mission, status, body/readiness, meaningful mission
and Door clocks, all21 slot names/IDs and complete Main/Scenario/MapGen RNG
buffers. The source of an input boundary is therefore another original native
phase, not a Rust-produced expected result. Named `phases` retain a small set
of lifecycle boundaries; `visits` records only state transitions.
Each boundary also reads the actual stored game speed at `0x00A8EB60`.
The inherited Construction fixture supplies speed3; complete options loading is
excluded. Normalized Anim constructor delays must use that observed input,
independently of the Rust lobby default or the production capture's speed.
All Commence calls retain their arguments and raw return register; only an
actual promotion (`AL != 0`) adds a return snapshot and transition. No-op
Commence calls do not duplicate unchanged world snapshots.

All three RNG objects are initialized once by original `0x0065C6D0` after the
inherited unrelated scene setup and before selected constructors. No phase is
reseeded. Original constructors, Unload's `RandomRanged(0,2)` rate suffix and
animation constructors may draw; full boundary buffers and actual ordered draw
requests are retained without a zero-draw assumption. The observer records
mission/Door/slot writes, allocation IDs, UnInit/expiry/destructor calls and
deferred deletion. `0x00451E40` clears the idle slot before scalar destruction;
the production Anim's real pointer-expiry callback creates Idle18 and clears
the old slot8 through the shared owners.

Inherited physical-byte/cache, allocation/delete, CRT TLS, Windows COM/audio
and presentation transports remain declared boundaries. Complete global

AI caller policy, blocked-world admission, rendering/audio output and whole
