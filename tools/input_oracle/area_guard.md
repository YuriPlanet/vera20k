# Original player Area Guard

`area_guard.py` composes the existing constructed `FootMissions` world with
`GIMoveHistory` invocation and Event observation. It executes unchanged
`gamemd.exe` instructions; it does not implement a second selection, mission,
voice, destination or Event encoder.

The selected route is a standing human-owned retail MTNK or E1 receiving G,
retaining its current navigation Cell as its Area Guard post, then entering the
ordinary handler. The admitted in-range enemy is another constructed MTNK.
Movement, locomotor Process, path completion, out-of-range pursuit, Fly/SCHP,
whole match loading and network scheduling are outside this witness.

## Reproduction

Run from the repository root with the existing prepared native inputs:

```sh
export VERA20K_SHRAPNEL_INPUTS=/path/to/vera20k_shrapnel_inputs/extract
export VERA20K_ANYTOWN_INPUTS=/path/to/vera20k_anytown_inputs/extract
export VERA20K_PROJECTILE_RENDER_ASSETS=/path/to/projectile-trailer-assets/extract
export VERA20K_FOOT_EMISSION_INPUTS=/path/to/foot-emission-reference-inputs/extract
python -m tools.input_oracle.area_guard --check
```

`VERA20K_GAMEMD_EXE` or the shared oracle's normal retail executable discovery
selects the binary. The sidecar records its identity and all loaded Python
sources. The first source snapshot includes helpers otherwise imported lazily;
publication rejects changes during generation or newly loaded unpinned helpers.
`--write --output /scratch/area_guard.json` stages a fresh executed result.

The retail reader rows use physical `RULESMD.INI`, absent `LANGRULE.INI`,
`MPBattleMD.ini` and `Hills.map`. The constructed actor/world histories retain
FootMissions' physical `XMP03T4.MAP` crop and its same four rules layers. Fixed
`ARTMD.INI` and `SOUNDMD.INI` are not layered. Both source chains and hashes are
retained; these are not claims that two distinct maps share whole-map state.

Before the histories, the existing Foot reader owners complete physical
GuardModeStray/IdleActionFrequency and weapon/child reads. Their actual outputs
are retained in `reader_receipts`; `handler_rules` and
`weapon_reader_projection` are compact readbacks for the Rust fixture. The
same shared Techno weapon reader/getter owner is applied to the actual MTNK
receiver using scoped Python fixture aliases, then the E1 aliases are restored.
This rebinds 105mm's Report after the selected sound registry is expanded;
native actor/type identity and all native field writes remain unchanged by
the adaptation. The histories therefore use the completed physical context,
not the older Foot corpus's intentionally retained pre-read controls.
`post_cells` independently invokes original Cell virtual `+48` before any
case for the two current posts and the other Cell post. It retains raw Cell
fields, returned XYZ and complete unchanged RNG states. A Rust fixture can
install these terrain inputs without deriving them from destination outputs.

## Reader and audio boundaries

Original Rules constructor `665650` initializes GuardSound to -1. Full
AudioVisual reader `6691E0` reads the exact `GuardSound` key through the native
128-byte string/reference lookup. Full TechnoType constructor `710AF0` gives an
empty special voice vector; the balanced `712CC5..712D2F` list block runs original
`525430`, assignment and temporary destruction. Retained defaults, missing,
empty, whitespace, unknown, duplicate/case, token whitespace, capacity and
wrong-case key histories are native outputs.

The shared `sound_inputs` owner runs original selected SoundList/Defaults/Voc
readers. Its fixture-local numeric IDs preserve the selected physical source
order. Stock E1 resolves GIMove's six physical samples; stock MTNK has no
VoiceSpecialAttack; GuardSound resolves CommandBar's `ucommand`. Authored type
reads occur while backend-present permits original `405170` name lookup; the
backend is disabled before the input histories. Original GuardSound `750920`
then executes its disabled-backend continuation. No mixer, decoder, device,
voice drain or sample-choice playback claim follows from a queued request.

## Scope and maintenance

The reused world supplies a human House, registry/count storage, physical crop
cells and native-seeded RNG state; original actor/type/locomotor constructors,
selected retail readers and actor Unlimbo execute. The source MTNK's inherited
queued Attack is visible before G, not relabelled as pristine mission state.
Successful allocator/CRT/OS input services are the existing fixture boundaries.
Each case restores all mapped bytes and CPU state between independent inputs;
this rollback is an experiment boundary, not game save/load behavior.

The older factory-produced input bootstrap rejects a stale inspection-helper
pin. It was not bypassed. An exploratory full local pump also needed its wider
factory/House/WinMM environment, so no result from that failed attempt is a
reference. This corpus keeps the existing constructor-built Foot route and the
explicit exact-record delivery boundary; it makes no full local/network pump
claim and changes no legacy native corpus.
