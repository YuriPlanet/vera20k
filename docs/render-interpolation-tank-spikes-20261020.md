# 坦克投影与插值捕获尖峰 — 第五轮，2026-10-20

## 为什么改这里

第四轮飞机优化完成后，用户要求再向坦克方向优化，并检查尖峰。
本轮发现：`RenderPose::read` 的精确高度分支先做 Z=0 的平面投影，再应用实际
高度；虽然第二轮已跳过外层 Z=0 的 lift，内部 `absolute_leptons_to_screen`
仍通过软件 x87 计算一次结果恒为0的 `AdjustForZ(0)`。新逻辑帧捕获全世界坦克
时也会反复进入这条路径，而不只是可见坦克的绘制。

生产改动仅为 `src/util/lepton.rs` 内一个严格等价的零高度快径：

```text
lift = Z == 0 ? 0 : original_native_x87_AdjustForZ(Z)
screen_y = original_projected_y + original_row_bias - lift
```

不改 signed XY 投影、子格合成、除法截断、f32转换或非零高度运算。
这是共享纯投影函数的优化，并非仅针对插值或坦克的特殊近似；其他使用同一投影
的消费者也可能受益。模拟状态、命令、RNG、存档、历史容器和采样策略均未改。
没有裁剪全世界捕获、跳过静止对象、降低频率、移动捕获时机或分摊逻辑帧。

## 正确性与性能方法

新增独立冻结旧公式的测试：保留原有 native-x87 调用，而非让两个包装器都调用
新快径。1,521组有符号边界XY/高度，加65,536组确定性宽域输入，共67,057组
屏幕XY浮点位值一致；显式验证 native AdjustForZ(0)==0。非零高度、728边界和
极值也纳入对照。另继续执行完整姿态、坐标、阴影与历史测试。

固定本轮前/后的 Release 测试二进制，原有10用例、世界/可见数量、MTNK零售
构造输入、提交/呈现时序、预热128、计时768、8对ON/OFF等均不改。交替顺序
为旧→新→新→旧，共两组，每版4次。最终每版每用例每模式32个运行均值。
保留全部原始慢样本，不过滤异常值。

特别区分：新逻辑帧时的插值 observe/capture CPU、普通呈现采样、组合P95与
最大值。这里的“提交尖峰”指观察到新逻辑帧后的**插值捕获工作**，不包含真实
模拟 tick、AI、寻路、GPU或系统呈现，不能称为整帧尖峰/FPS改善。

主探针：`app::presentation::interpolation::perf_tests::render_interpolation_paired_cpu_probe`
（`--ignored --exact --nocapture --test-threads=1`）。需零售INI环境且使用Release。
证据目录：`logs/interpolation-opt5-20261020/`；统计脚本为同目录`summarize.ps1`。

i5-12600KF / Windows 11 / Rust1.97.0，Release，受控平地零售MTNK姿态（精确Z=0）。

权威状态哈希一致。烟雾用例附带320个冻结的真实系统/粒子点，不计其物理更新。

### 20k 捕获及尾延迟

以下均为每次运行的对应统计量再取32次中位数，只有“全部样本最坏”取全局最大：

| 指标 | 本轮前 | 本轮后 |
| --- | ---: | ---: |
| 新逻辑帧插值捕获均值 | 2.31483 ms | 2.03979 ms |
| 捕获ON−OFF配对额外成本 | 2.31477 ms | 2.03972 ms |
| 捕获P95 | 2.42800 ms | 2.14365 ms |
| 捕获最大值的中位数 | 2.55740 ms | 2.26070 ms |
| 全部捕获样本最坏值 | 3.86230 ms | 3.53050 ms |
| 被测接口组合P95 | 2.56390 ms | 2.27425 ms |
| 组合最大值的中位数 | 2.81850 ms | 2.50505 ms |
| 全部组合样本最坏值 | 4.15750 ms | 3.85740 ms |

捕获均值约降11.9%，捕获P95约降11.7%。可见采样部分的均值为
0.11953→0.11617 ms；这是另一计时阶段，不能与捕获运行中位数机械相加成整帧。
本轮测到的最坏值降低，但系统调度会影响最大值，不构成最坏延迟上限。

**不是所有用例的最大值都改善。** 1k/250捕获最大值中位数为0.0468→0.0578 ms，
全局最坏为0.1013→0.1033 ms；组合最大值中位数0.1185→0.11955 ms。它的均值和
P95下降，但仍有尾部波动。这些样本没有剔除，不声称消除了所有卡顿。

因此结论限于：大规模受控坦克输入中，新逻辑帧插值捕获开销和常见尾延迟下降。
尚无真实整局的完整帧/FPS或模拟tick尖峰测量，不能保证200Hz时限，也不能把
第四轮飞机的局部比例与本轮相加。
