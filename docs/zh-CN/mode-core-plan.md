# 模式底座重构约束

## R04–R07 规则与会话状态

`MatchSpec` 在启动接纳时组合地图构造、规则策略和执行拓扑。`init.rs` 直接消费这份启动配置，把具名策略交给 `ScenarioDescriptor`。`ScenarioSession` 持有已接纳的权威 `RulePolicy`，仿真读取该值。原版模式用于选择默认预设和接纳旧数据。

木箱、`AllowWin` 与胜负、Paranoid、AI 建家、`DoubleOwned=`、小队及外交各有独立策略。构造期和会话期通过类型传递已选规则，移除枚举经布尔值转回枚举的转换。注册表与覆盖物加载器接收具体策略类型，调用方测试显式选择枚举值。`mod_additions.rs` 等行为入口消费具名策略，模式类分支归入原版预设。

`LocalViewIdentity` 独立持有其视角、跟随与本地发令来源字段。所有调用经由状态所有者读取。迁移验收检查平铺字段已经归并、共享哈希排除本地视角、守卫能拒绝旁路读写。守卫白名单不得因该迁移扩大。需要兼容的原版序列化字段由现有编解码边界保留。

离线遭遇战 mode 5 使用多人规则和本地执行，是必须保留的反例。单人战役 mode 0 也在本地执行，但使用战役规则。R04–R07 的相关行为链必须用这两个输入对照。回放保留记录的执行语义，地图构造仍使用已接纳的场景类别。

存档与回放验收覆盖历史原版样本、加载后的共享哈希和继续执行。单人战役、遭遇战（含 Teams 共享）与原版合作保留各自的存档及回放布局。独立规则值若进入新的持久化形态，必须在存档、回放和哈希协议中一并定义其恢复方式。

## Phase 2 发令来源与阵营权限

权限表按 `Source × House` 查找，目标是第三方 `House`，授权值区分 `FullControl` 和 `UnitsOnly`。N:1 共享主 `House` 的两个来源可持有不同授权。发令、锁步校验和回放恢复必须一直保留同一来源身份。验收时让两个来源共享一个主 `House`，对第一个目标分别授予 `FullControl` 和 `UnitsOnly`，对第二个目标仅授权其中一个来源，再从实际命令入口检查各自结果。

单人战役、遭遇战（含 Teams 共享）与原版合作是该模型的等价退化情形。控制授权检查保留原版规则和现有格式。`House` 供 AI、蓝图和原版玩法读取的人类属性仍由 `HouseState` 持有。

## R11–R12 回放依赖

原版启动与合作回放可各自沿现有入口推进。携带权限表的剧本蓝图须在 Phase 2 确立授权主体、索引与复原契约后接入，并用分别授权的共享 `House` 对局验证初始哈希和回放执行结果。

## Phase 4 房间信封

LAN 的已生效速度 `HostRoom.current_speed` 与设定速度 `options.game_speed` 各自传输和应用。房间信封迁移必须以两值不同的对照验证接收、显示和开局复制，并核对混版本与回滚路径。
