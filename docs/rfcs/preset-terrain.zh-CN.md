# 战区定义、桥梁与地面移动

[English](preset-terrain.md) · **简体中文** · [Deutsch](preset-terrain.de.md)

本提案供 VERA20K 开发者、MOD 作者和制图者评议。建议从一张有桥的遭遇战地图入手，先让同一份战区定义能供地图预览、正式对局和无头模拟使用，再贯通桥面变化、单位移动和建筑放置。上游可单独采用战区加载改动，版本预设由独立 fork 提供。[VERA Mod Engine](https://github.com/YuriPlanet/vera-mod-engine)

## 战区定义与游戏素材

现在加载温带战区时，`load_theater` 会挂载对应的 MIX，从战区 INI 的 `[TileSetNNNN]` 和 `[General]` 读取地块编号及 `BridgeSet`、`WoodBridgeSet` 等设置，再找 TMP 变体和调色板。第一项改动是让加载器接收已选定的战区定义。保留地块组的序号和范围、桥段编号的正负值，以及缺项与编号零的区别。同一份定义贯穿预览、开局和读档。按名查到 TMP 和调色板后，将影响通行或高度的数据计入对局校验。缺战区定义与缺某件素材应分别报出。[战区加载](../../src/map/theater.rs#L1048) · [遭遇战预览](../../src/app/shell_skirmish.rs#L81) · [无头开局](../../src/headless_scenario.rs#L536) · [读档](../../src/app/persistence/resource_load.rs#L142)

上游的零售模式可继续从安装目录读取原版定义。独立 fork 的安装目录只提供素材和选中的地图，包括 MIX 中的素材和用 INI 编码的战役地图。规则、ART、AI、战区、音效、EVA 和音乐目录由项目随附的版本预设提供。RA2 和 YR 各有独立的基础预设，Ares 在指定版本的 YR 预设上叠加差异。作者可随 MOD、模式或地图显式提供该层允许的覆盖。缺少必要定义时，开局前指出预设版本、来源和缺项。

## 类型 ID 与单位创建

第二步处理类型 ID。新定义用包名与类型名标识，旧 INI 段名与地图中的数字编号按本版规则解析。例如，地图新增一个类型时，早先规则中未注册的同名段不会被追溯套用。开局前解析引用、冻结本局的类型表与素材绑定。地图预放和对局中新生的单位各有实例 ID。已迁移字段直接写入现有 `RuleSet`，删去从合并 INI 再读一遍的旧逻辑。引用错误应能定位到文件、段名和键。[规则分层](../../src/rules/native_processing.rs#L264) · [类型索引](../../src/rules/ruleset.rs#L606) · [规则字段的现有读法](../../src/rules/ruleset/loading.rs#L1419)

第三步改普通地面单位的创建和移动。拟议的 `[Actor survey.Rover]` 可直接引用运动和占格定义，免填 `[VehicleTypes]` 序号及运动器 GUID。旧 `Locomotor`、`SpeedType`、`MovementZone` 标签由版本预设解释。地图预放、工厂生产和触发生成的同型单位从同一份定义取得能力，各自遵守所属方、任务和出场条件。增减 `Vehicle` 等 Flag 只影响筛选。单位具有运动能力且通过所属方和任务检查后，才能接受移动命令。[单位构造](../../src/sim/world/world_spawn/construction.rs#L64) · [现有运动器](../../src/rules/locomotor_type.rs#L34)

## 桥上、桥下与断桥

目前地形格记录地面及可用桥面，桥梁系统维护桥段状态，占格系统已有地面和桥面记录。普通单位寻路时从单位的 `OnBridge` 状态取得起始层，返回的路径队列保存行进方向。提案要求将目标层一直带到入格判定。同一组格坐标可以分别指向桥面和桥下，鼠标落点、寻路、占格及建筑地基检查都应能明确查询哪一层。[地形格](../../src/map/resolved_terrain.rs#L401) · [地面寻路](../../src/sim/movement/movement_tick.rs#L257) · [路径队列](../../src/sim/components.rs#L307)

桥被炸断或由工程师修复时，由现有桥梁系统提交变化，按游戏顺序处理受影响格的占用者、桥头通行和路径连通性。弹头结算、地块标记（CellTag）触发和同一逻辑帧后续的单位移动，各自在执行时读取桥况。建筑预览与正式放置查询同一套地基规则，下达建造命令时再查一次占格。桥面、单位位置和小地图从已提交的状态绘制。[桥段状态](../../src/sim/bridge_state/mod.rs#L273) · [占用者处理](../../src/sim/world/bridge_occupants.rs#L14) · [路径连通更新](../../src/sim/world/bridge_zone_publication.rs#L11)

没有桥的地图也可用来核对这项改动。开启地形变形后，一次满足条件的命中可压低地面并改变邻格坡面。下一次移动车辆、试放建筑和绘制弹坑时，都应读到已经提交的地形。关闭选项后，核对地形与随机数消耗是否符合原有行为。[地形变形](../terrain-deformation.md) · [地块更新](../../src/map/resolved_terrain/mutation.rs)

## 验收与后续

- **战区加载。** 先用同一张温带地图核对预览、客户端、无头和冷启动读档所得的地块编号、子块、高度与桥位。完成其余规则来源迁移后，用两份相同素材检查 fork。一份移去基础 INI，另一份保留改过的同名文件。启动、浏览器导入、读档及组房期间读取松散或 MIX 内基础 INI 的次数、写入原安装的次数都应为零。再用显式 MOD 或地图覆盖验证优先级和来源。
- **地面移动。** 只改一种地面的移动代价或通行许可，让地图预放和新生产的同型单位走相同路线，核对改道或到达帧。在高桥上下分别布置单位，过桥途中炸桥，再由工程师修复。检查各层占格、路径、伤害、触发次数及放置结果。断桥后存盘，冷启动读档，再与连续游玩、回放和双端锁步逐帧对照。独立 fork 为存档、回放和联机协议设新版本，旧格式或版本不匹配应在载入或进房时说明所需版本。
- **规模。** 用相同地图、种子和命令比较改造前后的 release 构建，在 20,000 单位、30 个参战方（House）的规模下记录逻辑帧耗时中位数、P95、峰值内存及终局状态校验值。[模拟基准程序](../../src/bin/sim-bench.rs)

首阶段面向使用 INI 和织网者的作者。弹道、附加效果（AE）和 Wasm 可在普通地面移动验收后继续讨论。上游 #4653 征求的是 Wasm 扩展接口的意见。HaoJun0823 提出的内容包和模块化 INI，以及 libi 对旧 INI、分阶段采用和 MOD 二次分发的回应，仍在原讨论串。这里用一个 MOD 和一张地图就能验证战区方案。[Wasm 扩展模块草案](https://github.com/YuriPlanet/vera20k/pull/4653) · [HaoJun0823 的建议](https://github.com/YuriPlanet/vera20k/pull/4653#issuecomment-7040998846) · [libi 的回复](https://github.com/YuriPlanet/vera20k/pull/4653#issuecomment-7042992589)
