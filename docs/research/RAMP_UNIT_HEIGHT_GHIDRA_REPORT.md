# Ordinary ground unit raw height on ramps

Native contract rechecked 2026-09-08 against the existing analyzed `gamemd.exe`,
image base `00400000`, SHA-256
`1cdd1180e49024fbda8ad568caac2e86e856063ff67ab38f62b7d2c7bb84298c`.
This is the bounded height producer prerequisite for the
[cliff depth plan](../plans/2026-09-08-cliff-unit-depth-plan.md).
It does not establish complete ground locomotion, bridge drawing, or pixel parity.

## Result and evidence boundary

Ordinary Drive, Ship, and Walk movement writes the object's absolute
`Location.Z` in leptons. It does not merely keep a tile level and ask drawing to
reconstruct the surface. The exact update cadence differs:

| Native operation | Raw Z behavior |
|---|---|
| Drive/Ship paid track point | Commit XY, resolve any crossing's OnBridge state, then `SetHeight(0)` |
| Drive/Ship final arrival snap | Commit destination coordinates, then `SetHeight(0)` |
| Drive/Ship residual interpolation | Commit interpolated XY with the previous raw Z; no height setter |
| Walk ordinary move, same/crossing cell | Commit XY, resolve crossing OnBridge if needed, then `SetHeight(0)` |
| Walk arrival | Commit destination coordinates, then `SetHeight(0)` |
| Idle Process paths | No blanket height normalization was found in these ordinary movement owners |
| Unit/Infantry type adjustment during Unlimbo | Preserve XY and return signed `max(inputZ, groundZ)` |

The movement cadence is established from live assembly and active callsites.
The setter, getter, terrain evaluator and type adjustment leaves additionally
have [158 executed native fixtures](../../tools/ramp_height_vectors.json),
generated by [ramp_height_oracle.py](../../tools/ramp_height_oracle.py). Those
fixtures do **not** execute the whole movement loops, Mark callbacks, or rendering.

## Raw coordinate copy and surface setter

Unit/Infantry `+0x1B4` dispatches through `4DB810`, which wraps raw coordinate
copy and optional Mark/cloak work. The actual copy `5F6940..5F695C` writes all
three supplied values verbatim to `Object+9C/+A0/+A4`. Contrary to the old
[FOOTCLASS_VTABLE_COMPLETE.md](https://github.com/YuriPlanet/vera20k/blob/108924bc237d14342b68b8bb78f2bba0400d2443/docs/research/FOOTCLASS_VTABLE_COMPLETE.md) description, this wrapper does not perform ground
or bridge height correction itself.

`Object+0x1CC -> 5F5FA0` takes a signed **height above surface** argument:

```text
offset = requested_height
if Object.OnBridge (+8C) != 0:
    offset = wrapping_i32(offset + [AC13BC])
Location.Z = wrapping_i32(578080(Location.XY) + offset)
```

`AC13BC` is the initialized 416-lepton bridge deck delta. The setter samples
the object's already-committed XY. It has no x87 arithmetic of its own; its
two final `ADD` instructions are ordinary wrapping 32-bit integer additions.
If `Object+74` is set, it surrounds the write with virtual `+124` REMOVE/PUT.
Ordinary same-cell movement suppresses that flag around the call.

Assembly: OnBridge test/add `5F5FAB..5F5FB5`; marked branch ground call/store
`5F5FF6/5F5FFF`; unmarked branch `5F603F/5F6047`.
The inverse getter `5F5F40` returns raw Z minus the same ground lookup and,
when OnBridge, minus the deck delta. These integer operations also wrap.

## Exact terrain lookup and arithmetic

`578080` divides each world X/Y by 256 **toward zero**, computes the fixed
`y*512+x` slot, checks the combined index and cell pointer, and forwards the
original low XY bytes to `47B3A0`. It is not equivalent to independently
rejecting each negative x/y component. A fixed-slot alias such as cell `(-1,1)`
can resolve the stored real cell `(511,0)`.

A missing/out-of-range slot falls back to the live shared dummy `ABDC50`,
stamping its coordinate at `ABDC74`. The dummy's **current signed level and
ramp** are evaluated. Returning constant zero is valid only when those fields
have their default zero values. Render-only callers must not acquire new
simulation mutations accidentally; sim-owned movement must preserve the
existing shared-cell authority and ordering.

`47B3A0` uses standard 104-lepton level height. Its numeric sequence is:

1. Sign-extend level byte `+11B`; integer multiply by 104, add floating 0.5,
   then native `ftol` chop. This matters for negative levels: flat level -1
   produces -103, not -104.
2. For nonzero ramp byte `+11C`, load the two unsigned low XY bytes and the
   ramp record. Compute the two coefficient products in their original x87
   order, each scaled by `104/256`, then add both record biases.
3. Clamp that ramp contribution before adding the rounded base. Apply final
   `ftol` chop to the sum.

Assembly: `47BA94..47BAB0` base; `47BAC7..47BB17` ramp arithmetic;
`47BB1D..47BB41` clamp; `47BB47..47BB4D` final addition/chop.
The oracle runs the native lazy table initializer and evaluator with ambient
FPCW `0x0E7F`; it does not replace ramp records with guessed coefficients.
See also [the 104-lepton ground-height census](https://github.com/YuriPlanet/vera20k/blob/108924bc237d14342b68b8bb78f2bba0400d2443/docs/research/PHASE3_CELL_GROUND_HEIGHT_104_DOMAIN_CONSUMER_CENSUS_GHIDRA_REPORT.md).

## Drive and Ship cadence and bridge ordering

Active Drive `Process` is `4B0500`; its ordinary moving branch calls
`Process_Drive_Track 4B0F20`. The common paid-point tail is:

```text
same-cell: suppress IsMarked; SetCoords(newXY, oldRawZ); restore flag
crossing: Mark(REMOVE); SetCoords(newXY, oldRawZ);
          update OnBridge; Mark(PUT); applicable cell work
if still alive:
    suppress IsMarked; SetHeight(0); restore flag
    continue facing/track/path work
```

Paid crossing OnBridge writes are `4B1830/4B184A`; Mark(PUT) is `4B1993`;
the height call is `4B1A96`, with explicit `PUSH 0` at `4B1A92`. Consequently
the height sample sees the **paid point's** containing cell and post-crossing
OnBridge, not a later residual point. Do not move the original common setter
before the crossing/Mark callback sequence when modeling same-tick consumers.

Final snap calls `SetCoords` then `SetHeight(0)` at `4B208A` (cross-cell) or
`4B20BD` (same-cell), before final Mark(PUT)/flag restoration. A zero-distance
final snap still reaches this setter. These are the only three `+1CC` calls
in the full 1655-instruction Drive track function.

Residual interpolation begins after the paid loop. Its interpolated delta Z is
zero, so all candidate XY paths retain the prior raw Z. On crossing it executes
`Mark(REMOVE) -> SetCoords -> OnBridge update -> Mark(PUT)` and returns
(`4B253F..4B25C3`). Same-cell residual suppresses IsMarked around the raw copy
(`4B25C6..4B25EF`). Neither path calls SetHeight or consumes a path queue node,
updates paid facing, or invokes PerCellProcess. A frame with no paid point can
therefore retain an earlier raw Z while XY/OnBridge changes. This small lag is
native behavior, not evidence that the setter or renderer is broken.

For an intact active nonterminal track, same-cell paid coordinates go through
`4B1A5A -> SetCoords 4B1A6B -> 4B1A77`; a different cell goes through
`Mark(REMOVE) 4B17CC -> SetCoords 4B17DC -> OnBridge 4B1830/184A ->
Mark(PUT) 4B1993`, conditional per-cell work, then the same `4B1A77` join.
Both reach `SetHeight(0) 4B1A96`. The point-index increment/store at `4B1F48/53`
and `budget > 7` back edge `4B1F50/56 -> 4B158F` admit more paid points.
Otherwise positive remainder is stored at `4B1F5C..67`, and an active track
continues through `4B1F88 -> 4B22D9` to residual interpolation. Native does not
unconditionally return merely because a paid point crossed a cell. Death,
callback exits and terminal track handling are separate gates.

Ship `Process_Drive_Track 6A05F0` has the same three-call structure:
`6A10D8` common paid point; `6A16CD/6A1700` final snap. Its residual path also
has no SetHeight call. These statements concern ordinary track motion, not
the separate Tube path or other locomotor ownership.

The crossing predicate remains the existing one: set OnBridge when destination
signed level equals source level minus four and destination flags include
`0x100`; clear when leaving a flagged source for an unflagged destination;
otherwise preserve it. Path-layer state is not a substitute for this byte.

## Walk cadence

`WalkLocomotionClass::ProcessMovement` has three SetHeight(0) callsites:

- Arrival `75BE01`, with its zero argument pushed at `75BDC8`, follows
  SetCoords `75BDC0` and packed-current-cell update `75BDF6`, before reservation
  work `FindSubCellDest 75BE18` and final Mark(PUT).
- Crossing `75C1A1` follows OnBridge writes `75C179/75C193` and precedes
  Mark(PUT) `75C1AE`.
- Same-cell `75C21C` follows SetCoords `75C20F`, with IsMarked suppressed.

All three use the new XY. Walk has no equivalent Drive residual path that
preserves the prior height after its ordinary coordinate update. Idle/blocked
early returns are not a reason to rewrite raw Z unconditionally.

## Placement and supplied altitude

Object Unlimbo `5F4EC0` calls the actual type's virtual `+6C` coordinate
adjuster, then raw SetCoords, then Mark(PUT). UnitType ctor writes primary
vtable `7F6218`; slot `7F6284` contains `747EB0`. InfantryType primary vtable
`7EB610`; slot `7EB67C` contains `5247D0`. Both bodies use signed CMP/JGE to
return `max(inputZ, 578080(inputXY))`, preserving XY. Neither adds bridge height.
Their code is present even though these two entries currently lack Ghidra
function boundaries; assembly and oracle execute the original bytes directly.

The authored Unit loader `743270` starts coordinate Z at zero. Its optional
OnBridge token sets `+8C`; true replaces Z with ground plus the Unit deck
constant (`74350A`, initialized `7352F0..735316`). Authored Infantry loader
`51FB00` first applies its selected subcell offset. When the OnBridge token is
present, false explicitly samples ground; true samples ground and adds the
Infantry deck constant (`51FDC4/51FDC9`). The latter constant is initialized
by `5179B0..5179D6` as `ftol(4*levelStep+0.5)`, 416 at the standard level step.

Infantry Unlimbo `51E030` additionally selects a free subcell when the supplied
Z equals its original ground sample. It passes the previous sample as the
candidate Z, and the type adjustment can clamp again at the selected XY.
The present height work does not certify this full selection/occupancy behavior.

VERA's existing reveal request carries coarse level, unlike native raw Coord.Z.
Translating a known authored on-deck coarse request to exact ground plus 416 is
an adapter to recover the native caller's intended input. It must be identified
as such, not described as a native universal Unlimbo rule. Elevated/parachute
positions must remain elevated; a generic unconditional ground snap is wrong.

The level-based adapter does not reconstruct every authored native input.
In particular, a non-bridge authored Unit on negative signed terrain starts
with native input Z=0; a supplied negative Rust level instead translates to a
negative candidate before clamping. Stock-map occurrence is not established.
Preserving raw caller coordinates through the entire placement API, and the
Infantry subcell reselection described above, remain outside this ramp producer
change. The native leaf fixtures cover signed arithmetic, not that whole caller.

## Other owners and exclusions

`ObjectClass::AI` calls SetHeight(0) at `5F3F7A` only on landing after its
falling-height update and GetHeight <= 0, then clears falling state. This is not
an idle ordinary-mover terrain normalization pass.

Hover, Fly, Jumpjet, Teleport, Tunnel, falling/parachute, and active low-bridge
Tube movement have separate height owners. Their existing exact altitude must
not be overwritten by this ordinary Drive/Ship/Walk producer. In particular,
finishing a Tube movement must not cause a generic end-of-tick ground pass to
erase that tick's final exact Tube position. Native Fly calls the same generic
setter with its own nonzero height arguments; sharing a leaf does not make it
an ordinary grounded mover. Full alternate-locomotor altitude contracts are
outside this bounded audit.

This work also does not repair the separate TooBigToFitUnderBridge/column-gated
split drawing path. Ground height, bridge drawing, and cliff depth are distinct
contracts even where they consume the same object Z.

Current Rust movement updates `OccupancyGrid` and `CellOccupationGrid`; its
ordinary crossings do not execute the complete native raw occupation-byte
REMOVE/PUT transaction. This predates the height producer. A live consumer is
`movement/path_markers.rs::build_bridge_passability_search`: eligible bridge
marker searches inspect raw ground occupation in their probe stencil and can
therefore observe older lifecycle marks. Movement tests of object-list layers
must not be described as raw Mark parity, or as proof of every bridge route.
The height change preserves the represented list ordering without expanding
that separate occupation mechanism.
