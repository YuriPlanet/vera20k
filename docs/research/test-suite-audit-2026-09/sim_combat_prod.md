## Systemic patterns (not direct deletions)

1. **The receiver_fixture compat shim changes production behavior under test.** `combat/receiver_fixture.rs` ("Compatibility inputs for phase-level tests … Adapters preserve the old phase's supplied state") plus 36 `#[cfg(test)]` branches in `world_receiver.rs` turn off death callbacks (`callbacks_enabled` → false, :5158), defer smudges instead of committing them (:133), override the tick (:5167) and sound/radiation (:5176-5190), and replace the tiberium prelude with a test-only formula (:82-97). 164 tests reach it (combat_tests 104, turret 13, aoe 9, fire_error_world 8, aircraft_release 7, cloak_damage 7, infantry_fire_facing 7, delayed_building 5, others 4). They test a production path that production never runs in that shape, and `kill_tick_unit_facing_holds_target` (:484) says so outright ("This receiver fixture disables the death callbacks, so it pins only the barrel"). Migrating them onto `advance_tick` would let receiver_fixture.rs (814 LOC) and the cfg(test) branches go.
2. **Hand-written unit tests shadowing native-oracle corpora.** kernel, factory cadence, weapon selection, threat range, veterancy, turret cadence, harvest field, and refinery dock all have a full oracle test next to 3-12 hand-calculated tests that pin subsets of the same rows. About 45 of the removals above are this pattern.
3. **Hand-copied "stock" INI excerpts instead of the production reader on retail INIs.** Examples: `combat_weapon.rs::stock_rules()` (:1236), `parasite_tests.rs` RULES ("copies retail rulesmd.ini values"), `stock_refinery_completion_rules`, `production_placement_tests` stock fixtures. They mirror retail data, which CLAUDE.md says to avoid when INI values decide the outcome, and they must be edited by hand when retail readers change.
4. MIGRATION naming (`gsi_NN_NN_`, P2/P3/P4/P5a, T5/T6, L2, S3, v3_, "legacy") appears on about 160 tests. The majority still assert native-derived behavior, so they should be renamed rather than deleted. Exceptions are listed above.
