# 通用 HUD 库技术实现方案

状态：库已实现，尚未接入任何宿主。细节以代码和测试为准。

## 1. 目标与非目标

目标：

- 提供与具体游戏无关的保留式 HUD：面板、按钮、文字、图片、进度条、宿主自绘区域。
- 支持大量世界对象的状态显示（基线 5000 个对象）和锚定绘制列表。
- 接口只传纯数据，将来脚本或沙箱模块可以通过一层薄桥接使用。
- 输入、布局、绘制顺序可预测、可单独测试，不依赖窗口和 GPU。

非目标：

- 不含任何游戏的布局、素材、规则、命令和命中特例。
- 不持有 GPU 对象，不解码资源，不整形文字。
- 不含脚本或沙箱运行时，也不定义其二进制接口。

## 2. 总体结构

```text
宿主状态 ──(只读、已按可见性过滤)──► 控制器 ──set──► Hud 节点树 ──layout──► 矩形
                                        ▲                                    │
                                        └────────── events ◄── input ◄───────┤
                                                                             ▼
对象视图 ──────────► World：状态模板、绘制列表 ──────────────────────► 有序绘制命令
                                                                             │
                                                                             ▼
                                                                    宿主渲染器（合批）
```

| 模块 | 文件 | 职责 |
|---|---|---|
| 核心 | `gui/src/hud/mod.rs` | 层、来源、节点生命周期、按名查找、revision |
| 布局 | `gui/src/hud/layout.rs` | 锚点、行列、裁剪、继承可见与可用 |
| 输入 | `gui/src/hud/input.rs` | 命中、捕获、悬停、滚轮、关闭、取消 |
| 绘制 | `gui/src/hud/paint.rs` | 有序命令、相邻合批 |
| 世界 | `gui/src/hud/world.rs` | 状态模板、锚定绘制列表 |

三种内容通道：

| 通道 | 适用 | 量级 | 更新方式 |
|---|---|---|---|
| 节点树 | 面板、按钮、列表式信息 | 数百个节点 | 变化时修改 |
| 状态模板 | 每个对象一份的状态显示 | 5000 个对象 | 声明一次，每帧批量求值 |
| 绘制列表 | 标签、连线、少量自由图元 | 数百份 | 内容变化时替换，位置每帧投影 |

对象状态不做成节点：调用方逐对象更新的成本随对象数增长，也让可见性过滤落到调用方手里。

## 3. 节点模型

- 节点用带代数的 `NodeId` 寻址。删除后旧句柄返回 `Stale`，槽位复用不会让它复活。
- `clear` 把属性恢复为默认值。
- 属性是带类型的值：布尔、整数、字符串、矩形、颜色、字符串数组。类型或节点种类不符时拒绝，原值不变。
- 每个节点记录来源：`Host`、`Layout`、`Player`、`External(n)`。`remove_origin` 一次移除该来源的节点（连同子树）、模板和绘制列表。
- `find(from, name)` 先找调用方自己的，再按来源顺序找；名字不区分 ASCII 大小写。
- 业务状态不放在节点里。删除或隐藏节点只影响显示和输入。
- 不保存回调、借用和 GPU 类型。

## 4. 分层

自下而上：

| 层 | 用途 | 规则 |
|---|---|---|
| `Field` | 世界上方、面板下方 | 不阻挡、不可点击时输入穿透到世界（仍可悬停） |
| `Panels` | 常驻面板 | 命中时消费输入 |
| `Overlay` | 临时浮层、外部内容 | 可声明点外面关闭 |
| `Modal` | 模态框 | 只有 `Host` 能创建和按名找到；有可见节点时挡住下面所有层和世界 |
| `System` | 退出、错误等紧急界面 | 只有 `Host` 能创建和按名找到，永远在最上 |

## 5. 布局

1. 显式 `Rect` 为绝对矩形，优先级最高。
2. 否则用九点 `Hold` 加 `X`、`Y`、`Width`、`Height`：节点与父节点的同名点对齐后偏移。
3. `Row`、`Column` 按顺序排列并应用 `Gap`；隐藏子节点不占位，缺省的交叉轴尺寸取父节点。
4. `Clip` 只影响后代，与祖先裁剪取交集。
5. `Visible`、`Enabled` 沿祖先继承。

算法：一次自下而上的测量、一次自上而下的放置，均为线性、非递归。坐标运算饱和，负尺寸按 0 处理。
几何修改在下一次 `layout` 生效，同一帧的输入和绘制看到同一份布局。隐藏立即对输入和 `rect` 生效。

## 6. 输入

- 先按层从上到下选层，层内按可配置策略选节点：点击可选“最上”或“树序第一”，悬停可选“最上”或“面积最小”。
- 只有可点击、可悬停或 `BlocksPointer` 的节点参与命中。禁用节点仍阻挡，但不激活。
- 每个鼠标键独立捕获：
  - 从世界按下：移动和释放都归世界，在面板上松手也能正常结束拖动；
  - 从 HUD 按下：移动和释放都归 HUD；
  - 期间出现模态框时，释放仍交给接到按下的一方。
- 点击默认在同一节点上释放时上报，`ActivateOnPress` 时在按下时上报。事件带鼠标键和命令名，命令由宿主执行。
- 外部来源的浮层不能独占 Escape 和“点外面关闭”：下面宿主的浮层照常关闭，并吞掉这次输入。外部浮层自己只吞世界上的按下，不吞 HUD 上的。
- 有模态框时 Escape 一律不交给世界。
- 节点被删除、隐藏、禁用或不再可点击时不会再被激活，按下仍归 HUD 到释放为止；失焦时用 `Cancel` 清理，不激活任何节点。
- `layout` 按指针最后的位置更新悬停和按下状态，可能产生悬停事件；`Cancel` 之后不再更新，直到指针再次出现。
- 事件队列有上限，悬停和滚轮会合并；命令名不超过 256 字节。

## 7. 绘制

`paint` 输出借用节点数据的有序命令：`Fill`、`Image`、`Text`、`External`，每条带节点和裁剪矩形。

- 顺序：层、根节点、先父后子；同一节点内为背景、图片或填充、文字。
- 不得把文字或图片跨越其他命令重排。
- `batches` 只合并相邻且裁剪、材质相同的命令。宿主想减少 draw，应使用共享图集，而不是改变顺序。
- 宿主负责资源名解析、字符串表、文字整形、实例缓冲和提交；缓冲跨帧复用，不为每段文字单独创建。
- 完全不可见（含 alpha 为 0 的填充）或在裁剪、视口外的命令不输出。

## 8. 状态模板

一份模板包括：

- 匹配：类型集合、类别位、关系位、状态位；
- 条件：值存在、未满、不低于阈值；
- 元件：分段着色的条、重复图片格、图标、数字；
- 数据源：`SourceId`，含义由宿主定义，新增数据源不改库。

每个对象最多 512 条命令，其中非宿主来源合计最多 384 条。非宿主模板放不下时，只略去它和其后的非宿主模板，
宿主的照常输出；单份就会超出份额的模板在注册时拒绝。

每帧宿主按绘制顺序提供已过滤的 `ObjectView`（句柄、投影后的位置、位集、数值）。求值顺序为对象、
模板注册、元件声明。输出带对象句柄，宿主据此决定深度。

输出矩形没有负尺寸，`x + w`、`y + h` 不溢出；锚定绘制列表同样如此。

性能要求：不按对象分配、不做字符串查找、类型集合在注册时排序。隐藏模板仍保留，便于撤销替换。

## 9. 锚定绘制列表

- 锚点：对象、世界格、屏幕点。图元：矩形、图片、线、文字，坐标相对锚点。
- 绘制时由宿主投影；不可见时返回 `None`，整份列表不输出。
- 镜头移动不需要调用方改写内容。

## 10. 帧流程

```text
1. layout(viewport)
2. input(event)；未消费的事件才交给世界
3. drain_events()；控制器执行命令
4. 在同一时点应用全部 UI 修改
5. layout(viewport)
6. world.paint_status(...)、world.paint_lists(...)
7. paint(...)：面板画在世界状态之上
```

宿主用 `Hud::revision`（含悬停和按下状态的变化）和 `World::revision`，加上自己的镜头、对象数据和视口版本，判断静止画面是否需要重画。

## 11. 外部客户端的接入边界

本库不实现桥接，只保证能被桥接：

| 将来桥接层负责 | 库已提供 |
|---|---|
| 句柄与整数互转、按实例隔离 | 带代数句柄、来源 |
| 写入和删除的权限检查 | 节点、模板、列表的来源查询，`Modal`、`System` 拒绝非宿主 |
| 按来源的节点、字节、调用额度 | 节点、模板、列表和每对象命令各有全局上限，各留四分之一（向上取整）只给宿主 |
| 撤销对他人内容的修改；卸载时预期他人句柄失效 | `remove_origin` 不撤销修改；它连同子树删除该来源的节点，他人建在其下的节点一并删除 |
| 事件路由 | 事件只带句柄，取出时节点可能已删除 |
| 枚举与属性的稳定编号 | 有类型、可穷举的枚举 |
| 数据读取的授权 | 只接受宿主过滤后的对象视图 |

库不是安全边界：不可信调用方必须经过桥接层，不能直接拿到 `&mut Hud`。

## 12. 原创 HUD 的接入步骤

1. 确定自己的设计：部件、尺寸、样式、素材、命令表。
2. 为每块面板写一个控制器：建节点、按状态更新、处理事件；游戏逻辑仍走宿主原有入口。
3. 实现一个渲染适配器：四种节点命令、五种世界命令，共用图集和实例池。
4. 用状态模板声明对象状态，不为每个对象建节点。
5. 按第 10 节接入帧循环，再做输入、缩放和性能验收。

## 13. 验收

| 项目 | 标准 |
|---|---|
| 单元测试 | 布局、裁剪、分层、捕获、关闭、极端数值、过期句柄、上限 |
| 黑盒测试 | 只用公开接口和纯数据完成：建面板、点击、模板、锚定列表、整体卸载 |
| 健壮性 | 任意整数输入不 panic；十万层嵌套不爆栈 |
| 世界拖动 | 在面板上松手仍能正常结束 |
| 顺序 | 合批前后命令顺序完全相同 |
| 5000 对象、release | 模板求值 p95 ≤ 1 ms |
| 300 节点、release | 布局与绘制列表合计 p95 ≤ 0.5 ms |
| 兼容 | 现有对话框栈的测试全部通过，依赖本库的 crate 能编译 |

实测（Apple M4、release、600 帧、两轮中较差的 p95；只含库内 CPU，不含 GPU 和文字整形）：

| 用例 | p95 | 命令数 |
|---|--:|--:|
| 5000 对象、1 份模板 | 0.051 ms | 10000 |
| 5000 对象、4 份模板 | 0.174 ms | 40000 |
| 500 份锚定绘制列表 | 0.002 ms | 1000 |
| 300 节点布局 | 0.009 ms | - |
| 300 节点指针移动 | < 0.001 ms | - |
| 300 节点绘制列表 | 0.003 ms | 360，合批后 290 |

复现：构建 `hud_bench` 示例（`gui/examples/hud_bench.rs`）后运行。

## 15. 已知限制

- 没有文本编辑、滚动容器、图标网格和动画；需要时随第一个使用者加入。
- 文字尺寸不参与自动布局。
- 命中为线性扫描，面向数百个节点；对象级显示走状态模板。
- 在接入第一个界面之前，接口只由测试和基准验证，可能随第一个使用者调整。
