# 插值姿态读取第二轮优化 — 2026-10-20

## 改动范围

继[第一轮历史缓存优化](render-interpolation-optimization-20261020.md)之后，
本轮仅合并 `RenderPose::read` 使用的屏幕投影和深度 lift 请求。历史结构、
采样公式、所有消费者、模拟事务、开关、存档和单逻辑帧显示延迟均未改变。

新增 crate-private `locomotor_visual::screen_position_and_lift`：精确 Z 对象
共享一次原有 native x87 AdjustForZ；精确 Z=0 的结果严格为 0，直接返回该值。
没有把非零高度换成近似浮点公式。无精确 Z 时仍调用原先两条路径，保留存储层级
投影和深度 lift 不同的语义。公开的旧函数保持原样。

单纯合并调用的第一候选没有稳定收益，未采用。候选 exe、源文件和包括异常慢轮次
在内的日志均保留。最终采用增加严格等价 Z=0 快径的第二候选，重新独立配对测量。

## 最终配对结果

环境为 i5-12600KF / Windows 11 / Rust 1.97.0，Release；输入同
[原始机制报告](render-interpolation-performance-20261020.md)。分别固定旧、新测试
exe，按旧→新→新→旧重复两组，每版 4 次完整运行。保留 1,280 条记录、983,040
次计时呈现迭代；每版每用例每模式的 32 个运行均值取中位数，不过滤慢帧。

下表均为 200 次呈现/秒、31.25 次提交/秒的受控回放。
**测量的是插值接口组合 CPU 成本，不是游戏整帧、GPU 或实际 FPS。**

| 世界 / 可见采样对象 | 优化前 ON | 优化后 ON | 被测时间下降 |
| --- | ---: | ---: | ---: |
| 100 / 100 | 0.01834 ms | 0.01811 ms | 1.3% |
| 1,000 / 250 | 0.05278 ms | 0.05157 ms | 2.3% |
| 5,000 / 500 | 0.14978 ms | 0.14431 ms | 3.7% |
| 20,000 / 500 | 0.52093 ms | 0.48112 ms | 7.6% |
| 1,000 / 1,000 | 0.20886 ms | 0.20488 ms | 1.9% |
| 1,000 / 250，320 个烟雾系统/粒子点 | 0.08608 ms | 0.08516 ms | 1.1% |

20k 的每提交配对额外捕获成本为 2.54713→2.30960 ms（下降约 9.3%）；
ON 的每运行 P95 中位数为 2.79765→2.55420 ms。旧 ON 运行均值范围约
0.51497–0.58413 ms，新约 0.47477–0.54112 ms，存在重叠，不将 7.6% 当作
任何机器/场景的保证。所有 640 组跨二进制对应运行及同版本 ON/OFF 的最终
权威状态哈希一致。

输入是平地、精确 Z=0 的零售 MTNK 姿态；烟雾点保持冻结。不能把本轮收益外推为
空军或混合战斗收益，也不能把两轮百分比相加当作 FPS 增益。普通 1k/250 OFF
中位数为 0.00909→0.00803 ms，BYPASS 为 0.00923→0.00812 ms，绝对量很小。

## 分段探针和验证

独立分段探针（8 轮均值的中位数）中，20k 旧完整姿态读取约 1.55577 ms，
合并读取约 1.44832 ms，预制姿态历史更新约 0.28389 ms，完整 observe 约
2.30239 ms。这些是不同循环、缓存状态且含重叠工作的测量，不可相加/相减当作
严格的成本分解。分段探针审计完整姿态及权威哈希。

- 新等价测试覆盖 2,340 个类别/坐标/层级/有符号精确高度/子格偏移组合；完整
  RenderPose 及所有浮点字段位值一致，包括 signed zero。
- Release `render_interpolation`：28 passed、4 ignored；主配对和分段探针另行执行。
- Release `app::presentation::`：239 passed、85 ignored；locomotor_visual：1 passed。
- 五项显式离屏 GPU 检查通过：插值 Kirov、变更后的第二帧上传、全局调色板、
  降落伞所属方 remap、维修附属效果。它们不代表整个游戏画面已验收。
- 正常游戏构建、相关文件 rustfmt 和 `git diff --check` 通过；已有警告不变。

## 模拟流程并没有现成的完整前后渲染姿态对

生产 `SimRuntime::advance_frame` 提供逻辑提交边界和当前权威状态；`SimFrameOutput`
没有完整的 previous/current render pose。当前原型在渲染前观察到新 binary frame
时读取一份当前姿态，把相邻帧的旧 current 保留为 previous；并非每次从世界重读
两份姿态。Facing 的旋转起点和移动路径端点也不等于全场景的前一逻辑帧姿态。
把捕获搬到提交边界本身不消除成本，追赶/隐藏帧时还可能增加捕获频率。本轮未改
模拟架构，未克隆第二权威世界。
